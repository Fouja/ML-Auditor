# Security

Security posture, hardening measures, and operational guidance for ML-Auditor.

## Secrets at rest (encryption)

Credentials stored in the database — currently `LLMConfiguration.api_key` — are
encrypted at rest before being written.

* **Algorithm:** Fernet (AES-128-CBC + HMAC-SHA256), from the `cryptography`
  package.
* **Key derivation:** the Fernet key is the base64-encoded SHA-256 digest of
  `SECRET_ENCRYPTION_KEY` when set, otherwise of `DJANGO_SECRET_KEY`.
* **Format:** stored values carry an `enc::` prefix. Legacy plaintext rows are
  detected and readable via `decrypt_secret` (they pass through unchanged) and
  are upgraded lazily by the model `save()` hook or by
  `migrations/0004_encrypt_llmconfiguration_api_key.py`.
* **Never serialized:** API responses (`list`, `get`, `create`, `update`,
  `active`) do not include the key. Outbound calls decrypt via the
  `LLMConfiguration.decrypted_api_key` property only.

### Rotating the encryption key

All `enc::` values become undecryptable if the derivation input changes. To
rotate:

1. Deploy the new `SECRET_ENCRYPTION_KEY` (or `DJANGO_SECRET_KEY`).
2. Re-encrypt every stored secret with the new key (a management command can be
   added; until then the data migration pattern in
   `0004_encrypt_llmconfiguration_api_key.py` shows the approach).
3. Verify with a decryption round-trip before discarding the old key.

## Key rotation for providers

* **NVIDIA NIM:** rotate `NIM_API_KEY` at build.nvidia.com. Re-deploy with the
  new value. If a key was ever committed or printed, rotate it immediately.
* **JobChameleon / EXA:** update `JC_API_TOKEN` / `EXA_API_KEY` in `.env` and
  restart the stack.

## Insecure defaults (removed)

* `docker-compose.yml` no longer ships fallback secrets (`django-insecure-…`,
  `dev-insecure-jobchameleon-token`, `changeme` passwords). These values are now
  pulled from the environment and **must** be provided.
* `config/settings.py` refuses to start with `DJANGO_DEBUG=False` while
  `DJANGO_SECRET_KEY` or `JWT_SECRET_KEY` is an insecure placeholder
  (`ImproperlyConfigured`).

## Generating secrets

```bash
cp .env.example .env
bash scripts/generate_secrets.sh   # idempotent; fills missing keys
```

See `scripts/generate_secrets.sh` — it fills `DJANGO_SECRET_KEY`,
`JWT_SECRET_KEY`, `SECRET_ENCRYPTION_KEY`, and `JC_API_TOKEN` with 50 random
characters and never overwrites existing values.

## Hardening checklist

- [ ] `.env` / `.env.prod` excluded from version control and never committed
- [ ] `DJANGO_DEBUG=False` in any environment that accepts real traffic
- [ ] `ALLOWED_HOSTS` set to explicit hostnames
- [ ] All secrets generated by `scripts/generate_secrets.sh` (≥ 32 chars)
- [ ] API keys stored via LLM Configuration are `enc::`-prefixed in the DB
- [ ] TLS enabled in front of the stack (see DEPLOYMENT_GUIDE.md)
- [ ] Provider keys rotated after any suspected exposure

## Tests

`backend/tests/test_crypto.py` covers encrypt/decrypt round-trip, plaintext
pass-through, idempotency, tamper handling, and model save/decrypt behavior.
